## 2026-07-21 — Fix resume-creation 402 error UX + gate bugs

**Bug:** POST `/api/resumes` returned HTTP 402 (Payment Required) for Free-plan users at the 3-resume limit. The block fired correctly per AGENTS.md rule #12, but the client showed a raw/generic error instead of an actionable upgrade prompt, and two latent gate bugs were present.

**Root cause:**
1. `ApiClient.request` threw a generic `Error`, discarding the 402 status — callers couldn't distinguish limit errors from other failures.
2. The route duplicated the limit logic with a hardcoded `>= 3`, bypassing the shared `gateFeature('resume_create')` helper (would silently drift if the limit changed).
3. `getResumeCount()` in `plan.ts` counted soft-deleted resumes (no `deletedAt IS NULL` filter), inflating the count shown on `/settings/billing`.

**Fix (5 files + 1 test):**
- `src/app/lib/api-client.ts` — added typed `ApiError` (carries `status` + parsed body); `request()` throws it. Backward compatible (extends Error).
- `src/app/lib/plan.ts` — `getResumeCount()` now filters `isNull(resumes.deletedAt)`.
- `src/app/api/resumes/route.ts` — replaced inline hardcoded gate with `gateFeature(user.id, 'resume_create', ...)`; preserved the `isBase ?? true` guard so tailored variants never hit the limit.
- `src/app/lib/resume-limit.ts` (new) — `handleResumeLimitError(err)` detects a 402 and shows a sonner actionable toast (Upgrade action → `/pricing`, with "delete a resume" hint). Framework-agnostic.
- `src/app/hooks/use-resumes.ts` — `useCreateResume` `onError` calls the helper; covers all callers (resume-detail, cover-letter page, upload-modal, chat-view).
